How it works — Agent Pipeline

Cortexa is built as a LangGraph state graph. Every question takes the same path: one router, one specialised agent, one answer writer.

  1. Input Your question Text, voice, a PDF or an image
  2. Node 1 Router Picks one of six routes, with a reason
  3. Node 2 Specialist agent Gathers the context for that route
  4. Node 3 Answer writer Writes the answer from that context
  5. Output Streamed answer With sources and page numbers
START → router → direct | wikipedia | tavily | arxiv | rag | image → llm → END

Step by step

  1. You ask

    Type, speak (Whisper turns your voice into text first), or attach a PDF or image.

  2. Your session is verified

    The backend checks your Supabase sign-in token and that any attachment is yours before doing anything.

  3. The router decides

    Attachments choose the route directly. Otherwise the router model returns a structured decision: one of six routes plus the reason.

  4. The agent gathers context

    Web results, Wikipedia or arXiv papers, the most relevant passages from your PDF, or the text and content of your image.

  5. The answer streams back

    The answer writer uses only that context and your recent chat history, and streams the reply live with its sources.

Shared state

Every node reads and updates one state object as the question moves through the graph:

  • query
  • route
  • route_reason
  • chat_history
  • tool_result
  • sources
  • document_id
  • image_ocr_text
  • image_vision_result
  • final_response

The streaming chat runs the same router → agent → answer steps and sends each stage and token to your browser as it happens.

PDF pipeline

From upload to a cited answer.

Ingestion

  1. Extract embedded text page by page (pypdf, PyMuPDF).
  2. Send only pages without text to OCR.space, with retries and an engine fallback.
  3. Clean the text and split each page into overlapping chunks.
  4. Embed chunks with FastEmbed (all-MiniLM-L6-v2, 384 dimensions).
  5. Store chunks with their page numbers in Postgres + pgvector.

Retrieval and answer

  1. Classify and rewrite the question for search.
  2. Hybrid search: vector similarity plus keyword match.
  3. Rerank, then keep diverse passages from different pages.
  4. Build the context with source, page and chunk labels.
  5. Answer only from that context and cite the pages.

Security and privacy

One sign-in system

Supabase Auth handles every password, code and Google sign-in. The app never stores passwords.

Your data stays yours

Chats, files and documents are always filtered by your account on the server.

Admin checked on the server

Admin pages need an allow-listed, confirmed email and the ADMIN role in the database.

Secrets stay on the server

API keys never reach the browser; it only gets Supabase's public key.

Untrusted content

Text from PDFs, images and web pages is treated as data; instructions inside it are not followed.

Honest answers

PDF answers come only from your document, with page citations you can check.
